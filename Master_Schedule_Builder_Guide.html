1. เริ่มใช้งานครั้งแรก — ทำครั้งเดียวต่อเครื่อง first time setup

  1. 1
    ซิงก์โฟลเดอร์แผนงานลงเครื่อง เปิดโฟลเดอร์แผนงานของทีมใน Teams หรือ SharePoint บนเว็บ → กดปุ่ม Sync / ซิงค์ ด้านบน → โฟลเดอร์จะไปโผล่ใน File Explorer ใต้หัวข้อ Coral Life
  2. 2
    เปิดเครื่องมือด้วย Chrome หรือ Microsoft Edge บันทึกลิงก์ไว้ในบุ๊กมาร์ก ใช้ได้ทั้งคอมพิวเตอร์และแท็บเล็ตหน้างาน
  3. 3
    กด เข้าสู่ระบบ / ทีม แล้วใส่อีเมลบริษัท + รหัสเข้าใช้งาน อีเมลต้องเป็น @coralesg.com · รหัสขอจากผู้ดูแล · ใส่ครั้งเดียว ระบบจำไว้ให้ — ชื่อคุณจะถูกใช้เติมช่อง “ผู้จัดทำ” ตอนบันทึกแผน
  4. 4
    กด เชื่อมไฟล์ถาวร แล้วเลือกไฟล์กลางของทีม ไปที่โฟลเดอร์ที่ซิงก์ไว้ในข้อ 1 → เลือกไฟล์ Master_Schedule_Data.json ที่ผู้ดูแลสร้างไว้ (อย่าสร้างไฟล์ใหม่) → ขึ้นแถบเขียวว่าเก็บถาวรแล้ว = เสร็จเรียบร้อย
ทำแค่นี้ทุกคนก็เห็นข้อมูลชุดเดียวกัน ทุกการพิมพ์บันทึกลงไฟล์กลางเอง และเครื่องมืออ่านไฟล์ซ้ำทุก 20 วินาที ถ้าเพื่อนร่วมงานแก้แล้ว จะดึงของล่าสุดมาแสดงให้เองพร้อมขึ้นข้อความบอก — ระบบจะไม่ไปกวนระหว่างที่คุณกำลังพิมพ์

2. กรอกแผนงาน 6 ขั้น build the schedule

  1. 1
    ตั้งค่าโครงการชื่อโครงการ · วันเริ่มงาน · ระยะเวลาสัญญา · เลือกวันทำงาน (จ.–ส. / จ.–ศ. / ทุกวัน) · ใส่วันหยุดพิเศษเป็น 2026-04-13 คั่นด้วยลูกน้ำ
  2. 2
    เลือกเทมเพลตเทมเพลตงาน → ฉบับ A งานอาคาร (WP-01…13) หรือ ฉบับ B บ้าน (B-1…8) มีช่วงรอ Main Contractor ปิดฝ้าคั่นให้แล้ว
  3. 3
    แก้รายการงานพิมพ์ทับได้เลย · ชื่องาน/รหัส WBS/ผู้รับผิดชอบ เลือกจากรายการที่มีให้ · ปุ่มท้ายแถว ↑ ↓ เลื่อน · ⧉ ทำซ้ำ · ✕ ลบ
  4. 4
    กด คิดน้ำหนักอัตโนมัติเกลี่ยน้ำหนักตามจำนวนวันให้ครบ 100% แล้วปรับงานที่มีมูลค่าสูงเพิ่มเอง
  5. 5
    อัปเดตทุกสัปดาห์ใส่ช่อง ทำแล้ว % ของแต่ละงาน แถบ KPI จะบอกทันทีว่าแผน ณ วันนี้กี่ % ทำได้จริงกี่ % ช้ากว่าแผนเท่าไร
  6. 6
    กด บันทึกแผนงาน (ออก Rev.) ทุกครั้งที่แก้เสร็จ ต้องใส่ชื่อผู้จัดทำและวันที่ทุกครั้ง ไม่ใส่จะบันทึกไม่ผ่าน · ระบบเลื่อนเลข Rev. ขึ้นให้เอง (R0 → R1 → R2) และเก็บลงตาราง ประวัติการออก Rev.

3. ช่องไหนต้องกรอก ช่องไหนไม่ต้อง what to fill in

  • ช่องพื้นเหลืองขอบทอง = ต้องกรอก ยังว่างอยู่ · พอกรอกแล้วสีหายเอง
  • ช่องพื้นเทา = ระบบคำนวณให้ (วันเริ่ม / วันเสร็จ) ไม่ต้องไปยุ่ง
  • จุดแดงท้ายชื่อช่อง ในข้อมูลโครงการ = ช่องบังคับ
  • ป้ายที่หัวตาราง บอกว่ายังเหลือกี่ช่อง กดแล้วกระโดดไปช่องนั้นให้เลย · กรอกครบเปลี่ยนเป็นป้ายเขียว
  • บังคับกรอกจริง ๆ มีแค่: ชื่อโครงการ · วันเริ่มงาน · ระยะเวลาสัญญา · ชื่องาน · จำนวนวัน
  • อยากให้ตารางเรียบง่ายขึ้น เลือก มุมมอง → ง่าย จะเหลือเฉพาะช่องที่ต้องกรอก

4. คอลัมน์ที่ต้องเข้าใจ columns

เริ่มหลังจากงานที่ต้องเสร็จก่อน — ตัวที่ทำให้แผนทั้งสายเลื่อนตามกัน
ชนิดFS เริ่มหลังงานก่อนเสร็จ · SS เริ่มพร้อมกัน
Lagเว้นกี่วันทำงาน · ใส่ติดลบได้ ถ้าต้องการให้งานคาบเกี่ยวกัน
วันระยะเวลา นับเฉพาะวันทำงาน ข้ามวันหยุดให้เอง
น้ำหนัก%สัดส่วนของงานนั้นในโครงการ รวมทุกงาน = 100%
ทำแล้ว %ความคืบหน้าของงานนั้นเอง 0–100 (เสร็จแล้ว = 100)
MSติ๊ก = Milestone / Hold Point ★ แสดงเป็นข้าวหลามตัดแดง
รอผู้อื่นช่วงที่เราไม่ได้ทำ เช่นรอปิดฝ้า — กินเวลาแต่ ไม่นับน้ำหนักและผลงาน
ข้อผิดพลาดที่พบบ่อยที่สุด — “ทำแล้ว %” ไม่ใช่ “น้ำหนัก%” งานที่เสร็จแล้วให้กรอก 100 ไม่ใช่กรอกน้ำหนักของมัน (เช่น 7.6) ระบบจะคูณน้ำหนักให้เอง ถ้ากรอกผิดแบบนี้ แท่ง Gantt จะเติมสีนิดเดียวและ KPI ผลงานจริงจะต่ำผิดปกติ — เครื่องมือตรวจจับให้และขึ้นปุ่ม “แปลงให้อัตโนมัติ” กดครั้งเดียวแก้ทั้งตาราง

5. บันทึกและติดตาม Defect defects

  • กด + เพิ่ม Defect — ระบบเติมให้อัตโนมัติ: วันที่วันนี้ · งานที่กำลังทำ · รหัส WP · ผู้แก้ไข
  • กำหนดแก้คิดให้ตามมาตรฐาน — Critical = วันทำงานถัดไป · Major = วันเสร็จของ WP นั้น · Minor = วันส่งมอบ (แก้ทับได้)
  • แถวขีดแดงซ้าย = เกินกำหนดแก้ · ขีดเหลือง = Critical ที่ยังค้าง
  • งานที่มี Defect ค้างจะขึ้นตรา ▲ ตัวเลข ใน Gantt · คลิกที่ตราเพื่อกรองดูเฉพาะงานนั้น
  • เปลี่ยนสถานะเป็น Verified / Closed แล้วระบบลงวันที่แก้เสร็จให้เอง
  • กฎที่ระบบเตือนให้: ห้ามผ่าน Hold Point ★ ถ้ายังมี Defect ค้าง · กรอกทำแล้ว 100% ทั้งที่ยังมี Critical ค้าง · Defect เกินกำหนดแก้

7. พิมพ์เป็น PDF print

  • กด พิมพ์ / PDF → เลือกกระดาษ A3 แนวนอน → Save as PDF
  • ระบบ ย่อ Gantt ให้พอดีหน้ากระดาษเอง โครงการยาวจะสลับเป็นมุมมองรายเดือนให้ก่อน
  • ตารางยาวขึ้นหน้าใหม่พร้อม หัวตารางซ้ำทุกหน้า และไม่มีแถวถูกผ่าครึ่ง · Gantt ขึ้นหน้าใหม่เสมอ

8. ทำงานพร้อมกันหลายคน working together

  • ไม่มีระบบล็อกกันคนแก้ — ใครแก้ก็ได้ตลอดเวลา ไม่มีอะไรมาขัดจังหวะ
  • ความรับผิดชอบอยู่ที่ การออก Rev. — ทุกครั้งที่บันทึกต้องลงชื่อและวันที่ ตรวจย้อนได้เสมอว่าใครแก้เมื่อไร
  • เครื่องมือดึงของใหม่จากไฟล์กลาง ทุก 20 วินาที ถ้าเพื่อนบันทึกไป จะขึ้นข้อความบอกและอัปเดตให้เอง
  • วิธีเลี่ยงงานทับกัน: ตกลงกันให้แต่ละคนดูแลคนละโครงการ (คนละแท็บด้านบน) หรือแก้ทีละคนแล้วบอกกันในไลน์
  • ถ้าสองคนแก้โครงการเดียวกันพร้อมกันจริง ๆ OneDrive อาจสร้างไฟล์ “สำเนาที่ขัดแย้ง” ขึ้นมา — แจ้งผู้ดูแลให้รวมไฟล์

2. ติดตั้งครั้งแรก — วิธีที่ใช้อยู่ simple setup

  1. 1
    เตรียมโฟลเดอร์บน SharePoint / Teams ใช้โฟลเดอร์ของทีมที่ทุกคนเข้าถึงได้ ตั้งสิทธิ์เป็น แก้ไขได้ ให้คนที่ต้องกรอกแผน
  2. 2
    กด Sync ที่โฟลเดอร์นั้น โฟลเดอร์จะไปโผล่ใน File Explorer ใต้ Coral Life — ให้ทุกคนในทีมทำข้อนี้ด้วย
  3. 3
    สร้างไฟล์กลางด้วยเครื่องมือ เปิดเครื่องมือ → เชื่อมไฟล์ถาวร → เลือกโฟลเดอร์ที่ซิงก์ → ตั้งชื่อ Master_Schedule_Data.json → Save (ทำครั้งเดียวโดยคุณคนเดียว)
  4. 4
    ตั้งรหัสเข้าใช้งานของทีม เข้าสู่ระบบ / ทีม → ใส่อีเมลผู้ดูแล → ส่วนตั้งค่าจะโผล่ → กรอกรหัสที่ต้องการ → บันทึก (รหัสตั้งต้นคือ CORAL-ERV-2026)
  5. 5
    บอกทีมงาน 3 อย่าง ลิงก์เครื่องมือ · รหัสเข้าใช้งาน · และให้ทำตามส่วนที่ 1 ข้อ 1–4 ของคู่มือนี้

  • สำรองข้อมูล: กด สำรองทุกโครงการ ทุกสิ้นสัปดาห์ ได้ไฟล์ .json รวมทุกแท็บ · OneDrive เก็บประวัติเวอร์ชันย้อนหลังให้อีกชั้น (คลิกขวาที่ไฟล์ → ประวัติเวอร์ชัน)
  • กู้คืน: เปิดไฟล์ แล้วเลือกไฟล์สำรอง — ระบบถามก่อนแทนที่ทุกโครงการ
  • ส่งเฉพาะโครงการเดียว: บันทึกโครงการนี้ ได้ไฟล์เดียว ผู้รับกด เปิดไฟล์ จะเข้าเป็นแท็บใหม่ ไม่ทับของเดิม
  • เจอไฟล์ “สำเนาที่ขัดแย้ง” ในโฟลเดอร์: แปลว่ามีคนแก้พร้อมกัน — เปิดทั้งสองไฟล์ในเครื่องมือ (คนละแท็บ) เทียบว่าอันไหนใหม่กว่า แล้วลบอีกอันทิ้ง
  • ใครแก้อะไร: ดูตาราง ประวัติการออก Rev. ในหน้าเครื่องมือ — บันทึกผู้จัดทำ วันที่ และรายละเอียดทุกครั้งที่บันทึก

5. อัปเดตตัวเครื่องมือ deployment

  • ไฟล์ต้นฉบับอยู่ที่ Desktop\Dashboard\Master_Schedule_Builder.html — แก้ไฟล์นี้ไฟล์เดียว
  • ดับเบิลคลิก Update Dashboard to GitHub.bat เพื่อส่งขึ้นเว็บ (พาคู่มือขึ้นไปด้วย) ขึ้นจริงภายใน 1–2 นาที
  • บอกทีมให้กด Ctrl+F5 หลังอัปเดต เพื่อล้างแคชเบราว์เซอร์
  • ข้อมูลของทีมอยู่คนละที่กับตัวเครื่องมือ — อัปเดตเครื่องมือไม่กระทบข้อมูล

6. ถ้าจะอัปเกรดเป็นโหมดทีม M365 ภายหลัง optional upgrade

ทำเมื่อเจอปัญหาแก้ชนกันบ่อยจนสำเนาที่ขัดแย้งเยอะ — โหมดนี้ตรวจเวอร์ชันให้ก่อนเขียนทุกครั้ง

  1. 1
    ลงทะเบียนแอปใน Entraentra.microsoft.com → App registrations → New registration → ชนิด SPA → Redirect URI = ลิงก์ของเครื่องมือนี้
  2. 2
    ให้สิทธิ์ Microsoft GraphAPI permissions → Microsoft Graph → Delegated → Files.ReadWrite.All + User.Read
  3. 3
    กรอกค่าในเครื่องมือเข้าสู่ระบบ / ทีม → อีเมลผู้ดูแล → กรอก Client ID, Tenant ID และวางลิงก์แชร์ของโฟลเดอร์ (ระบบหาไฟล์ข้อมูลในโฟลเดอร์ให้เอง ถ้าไม่มีจะสร้างให้)
ข้อจำกัดที่ต้องรู้ เว็บที่วางเครื่องมือเป็นพื้นที่สาธารณะ ใครมีลิงก์เปิดหน้าเครื่องมือได้ แต่เปิดข้อมูลไม่ได้ถ้าไม่มีสิทธิ์ที่โฟลเดอร์ ต้องใช้ Chrome หรือ Edge — ปุ่มเชื่อมไฟล์ถาวรไม่มีในเบราว์เซอร์อื่น เน็ตล่มก็ยังทำงานได้ เพราะเขียนลงไฟล์ในเครื่อง OneDrive จะซิงก์ให้เมื่อเน็ตกลับมา

7. แก้ปัญหา admin troubleshooting

อาการสาเหตุและวิธีแก้
ทีมงานไม่เห็นปุ่มเชื่อมไฟล์ถาวรใช้เบราว์เซอร์อื่นที่ไม่ใช่ Chrome/Edge หรือเปิดจากไฟล์ในเครื่องแทนลิงก์ https
เลือกไฟล์แล้วข้อมูลไม่ตรงกับของคนอื่นเลือกคนละไฟล์ — ตรวจว่าเป็นไฟล์ในโฟลเดอร์ที่ซิงก์ ไม่ใช่ไฟล์ที่ตัวเองสร้างใหม่
มีไฟล์สำเนาที่ขัดแย้งเกิดขึ้นบ่อยแบ่งกันดูแลคนละโครงการ หรืออัปเกรดเป็นโหมดทีม M365 (ข้อ 6)
ข้อมูลหายหลังล้างประวัติเบราว์เซอร์เครื่องนั้นยังไม่ได้เชื่อมไฟล์ถาวร — ให้ทำส่วนที่ 1 ข้อ 4
โหมด M365: ขึ้น redirect_uri mismatchRedirect URI ใน Entra ไม่ตรงกับลิงก์ที่ใช้เปิด — ต้องตรงทุกตัวอักษรและเป็นชนิด SPA
โหมด M365: ขึ้น need admin approvalองค์กรตั้งค่าห้ามผู้ใช้ยินยอมเอง — ต้องให้ผู้มีสิทธิ์ Global Admin กด Grant admin consent
